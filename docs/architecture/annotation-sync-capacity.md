# 笔迹内容与同步容量

笔记继续使用对象操作、版本冲突和本机待同步队列，沿用 [ADR-0009](../adr/0009-use-object-operations-with-d1-optimistic-concurrency.md)。本次 #412 只缩小表示并限制单批体积，不改变 API、D1 或 IndexedDB 数据格式。

## 写入预算

- 客户端每个请求最多 100 条操作，普通请求的 UTF-8 JSON 预算为 512,000 字节。预算计算包含 `{"operations":[]}`、操作之间的逗号以及完整线上字段；本机归属、时间戳等字段不参与请求。`prepareAnnotationPush` 和发送方共用 `toWireOperation`，防止计算与实际发送格式漂移。
- 客户端按现有重试优先级和对象顺序选择前缀。超过预算的合法单条操作允许单独发送，避免长笔迹永久卡住；本轮未选操作不标记为已尝试。失权与冲突对象继续遵守已有筛选规则。
- 服务端数据库参数只包含操作身份、`payloadJson` 及哈希，不重复包含 `payload`。payload 字符串的转义也计入最终序列化 UTF-8 大小。
- 服务端每个 JSON 数组参数采用 1,900,000 字节预算，低于 [D1 的 2,000,000 字节字符串限制](https://developers.cloudflare.com/d1/platform/limits/)。相同笔记对象或操作 ID 仍会开启下一波，以保持请求顺序。所有波的 SQL 仍放进同一个 `db.batch()`，保留事务和权限复核语义。

当前 schema 最多允许一条笔迹 5000 点，每个点的六个数字和操作字段均有界，单条合法操作的转义后大小低于服务端预算。修改点数或字段上限时必须重新核查单条参数上界，而不能只调整批次大小。字节预算不代表对任意巨大请求的内存或 CPU 成本都已作出保证。

## 新采集笔迹

`NoteInteraction` 只在开始、移动和收笔采集时调整新点：

- 归一化 x/y 舍入为 5 位小数。在某一坐标轴对应 4096 像素时，最大坐标舍入误差为 0.02048 像素；这不是全部渲染误差的上界。
- 省略值为零的 `tiltX`、`tiltY`、`twist`，保留非零值。读取和荧光笔旋转计算已经支持字段缺省。
- 保留压力原始精度，即使当前笔迹是等宽模式；后续切换压感模式仍可使用原始压力。
- 保留点的时间顺序与数量，包括荧光笔折返和旋转。原有 5000 点输入缓冲规则不变。

已有对象的移动、属性修改、离线恢复和同步队列不会经过新点采集转换。尤其不能在发送或服务端入库时重写已排队 payload：相同 opId 的重试必须保持原始载荷和哈希身份。

## 采样点简化的评估结论

现有 `highlighterSamples` 是绘制阶段的几何简化，不是通用的持久化转换。它保留荧光笔折返和扁头旋转，但没有用于普通笔的压力变化判定；普通笔的平滑/streamline 也依赖输入采样。

合成直线样本中，300 点经该算法只剩 2 点。压力由 0.05 平滑升高再降低时，按当前 `perfect-freehand` 参数在 4096 像素宽页面绘制，最大笔迹厚度由 17.8174 像素变为 12.2880 像素。即使中心线相同，也不能保证外观相同。

因此本轮不把绘制简化结果写回存储。未来若实现压力感知简化，必须同时验证压力峰值、转折、折返叠色、旋转以及属性切换/导出；不能仅凭点数减少或中心线误差证明视觉兼容。

## 发布与恢复

1. 先发布支持服务端内部拆批的 Worker，让已部署客户端的大批操作也能受益。公开 API 仍接受最多 100 条，不降低旧客户端条数上限。
2. 再发布客户端字节组批和新点采集调整。旧客户端继续读取相同对象 JSON，零值角度本来就是可选字段。
3. 不执行 D1/IndexedDB schema 迁移，不批量重写历史笔迹、不重新生成待同步 opId。
4. 回退客户端不会破坏新笔迹读取。但回退服务端会重新暴露旧客户端大批写入的 D1 容量边界；优先修复前进，不把服务端回退当作容量问题的安全修复。

具体样本体积及本地验证见 [#412 验证记录](../verification/issue-412.md)。
