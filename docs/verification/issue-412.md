# #412 笔迹体积与同步字节预算

基线：`8651210c98484b39129e5ec4d384f4b0c85ed8ed`。本次在独立 worktree 实施，无生产数据写入或部署。

## 合成样本证据

300 点固定压力笔迹，设备角度均为零。坐标构造为 `x=(127+i*1.73)/1024`、`y=(615+sin(i/299*2π)*93)/1448`，`i=0..299`，压力 0.5。payload 含 pageNumber=1、kind=ink、brush=pen、nib=round、pressureMode=uniform、strokeWidth=0.003。

| 表示 | UTF-8 JSON 字节数 |
| --- | ---: |
| 当前表示 | 26,871 |
| 省略零值角度 | 17,871 |
| 再将 x/y 舍入到 5 位小数 | 12,344 |

该样本减少约 54%，不是线上平均收益；压力精度和点数未减少。它与此前 1.94 MB 的边界样本是不同的构造，不应混为同一测量。

同一 payload 配置 100 条不同笔记对象操作时，请求 2,706,516 字节；旧数据库参数 5,772,901 字节；删除重复 payload 后，未拆批参数仍有 3,084,701 字节。因此去重与字节拆批必须同时实施。

采样点简化的反例和保留原始点的原因见 [容量设计](../architecture/annotation-sync-capacity.md#采样点简化的评估结论)。

## 回归边界

- 公开 push/pull API：99 个长笔迹创建加同对象连续更新，保留结果顺序、版本、拉取内容；整批重试不增加版本。测试对真实本地 D1 的绑定边界施加官方 2 MB 字符串限制，因为模拟器本身未执行该限制。
- 客户端队列/同步：100 条中文文本与长笔迹分为有界 UTF-8 请求；大于常规预算的单条旧笔迹单独上传，丢失响应及数据库重新打开后保持 opId 和完整原始 payload，再继续上传小笔记。
- 笔迹采集与恢复：新点坐标缩短、零值角度缺省，压力（含零值）和非零角度恢复完整。现有编辑、撤销、冲突、失权用例继续运行。
