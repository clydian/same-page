# 练习看谱布局与真实合唱谱校准 · #431

## 范围

手机、iPad 和桌面共用顶部谱面切换与结束、底部播放控制；MusicXML
重排大小由播放器自身调整。PDF 复用原阅读器的页面、手势和笔记显示，练习中仅保留浏览与页码总览。
本次没有数据库、服务端 API、笔记或持久偏好格式迁移。

## 回归覆盖

`browser-tests/practice-reader-layout.test.mjs` 使用可公开提交的生成谱例，包含
弱起 `0` 与自定义 `25` 小节标号；Chromium/WebKit 检查 320×740、390×844、
844×390、820×1180、1180×820。

- 控制按钮及速度选择器触摸高度至少 44px，当前小节可见，谱面避让上下栏。
- 坐标拖动预览目标，释放才定位，前后小节仍按播放次序移动。
- 原始 XML 小节标号与重复展开后的播放次序分别保留，自定义标号也用于重排谱面。
- 首调数字首次默认全部声部；大小调整重排并保留手动浏览位置、播放位置和跟随状态。
- 触摸点击 PDF/XML 切换；PDF 不唤起普通工具，页码总览仍可用；结束后恢复普通阅读。
- 原有 MusicXML 合成声音、循环、混音、准备复用与公开体验本机笔记边界回归继续保留。

`playback-timeline.test.tsx` 检查取消、键盘、辅助输入和释放到轨道外的行为。
WebKit 原生 range 在 pointer 仍按住时会产生 element blur；事件记录为
`pointerdown → input → blur → input`。元素失焦只提交键盘操作，pointer 继续预览到
释放；window blur 或 pointercancel 取消。回归同时保留这一真实浏览器路径及其最小组件用例。

## 追加：每次打开从头开始

删除跨次播放偏好读取和写入；每次明确打开附件都建立新会话，从第一个小节、
1× 和默认混音开始。同次 PDF/XML 切换继续保持会话。已有本机偏好值不再使用，
也不批量删除。组件与浏览器回归覆盖旧偏好值不影响初始状态、结束重开后进度/速度/关注归零，
以及同附件前一会话的迟到失权请求不能关闭新会话。

本地可操作预览使用《舟中晓望》真实 XML，以及原 PDF 前两页的独立副本；
预览数据和截图不进入生产或公开仓库。手机对照截图实际记录关闭前第 17 小节／0.75×、
重开后第 1 小节／1×；另保留 iPad 重排谱面和原 PDF 截图供确认。

追加改动验证：Node 24 下 lint、生产 build/typecheck、完整客户端 999 项、
会话/lifetime 定向 11 项均通过；Chromium/WebKit 播放、非零位置结束后重开、
旧偏好忽略、PDF 切换完整流程 2/2 通过。独立 Standards 与 Spec 追加 review 无阻塞项。

生成谱例包含 0、25、自定义编号以及两小节反复；第一次经过与回跳后的提示均核实。

## 追加：真实谱密度反馈修正

用户试用揭示前述 80% 默认／60% 下限校准不足。完整六行合唱及钢琴谱《舟中晓望》
在手机 390px、60% 时，98 小节约 95 行，其中 92 行仍只有一小节，开头连续单小节。
此前截图验证了大小变化，却不足以证明每行容量明显改变。

独立 alphaTab 原设置／源换行／缩放对照定位：主要限制是密集伴奏的自然宽度及
过高的缩小下限；XML 的打印换行还会限制更小比例时的重排，清除换行本身不足以解决
60% 下的容量。默认调整为 60%，开放 30%–120%，清除内存 model 的打印换行／分页。
不强制两小节一行，也不改源文件。30% 提供用户选择的概览密度，歌词会明显变小。

回归使用公开生成 XML 在每小节放置打印换行，检查仍按屏宽合并多小节；同时检查
30% 下限、120% 上限，以及实际系统行数在缩小时减少，继续保留播放位置、标注、
手动浏览锚点和手机/iPad 布局验证。真实谱与对比截图留本机。

三首真实谱在 390×844 与 820×1180、60%／30% 下完成 12 张对照。
首调数字随谱面同比调整字号及间距（最小 5px），避免缩小时固定 9px 标注挤在一起。
锚点回归延长为 128 小节，以在更紧凑默认下保留足够滚动空间，避免触及文档末尾。

完整播放与更新后的密度／缩放／锚点布局流程通过。Standards / Spec 独立复核无阻塞项，
