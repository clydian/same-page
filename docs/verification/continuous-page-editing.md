# 连续布局中的逐页编辑

本阶段基于渲染恢复分支 `fix/continuous-render-recovery`（`4e6f807`），应以 stacked PR 审核，先合入第一阶段。没有修改 API、IndexedDB、已保存笔记或 PDF 版本格式。

连续布局不因编辑而折叠、重新缩放或按输入页跳动。可见页共享一个 `AnnotationEditor`，各页通过 `AnnotationPages` 管理输入归属：输入页与视口中心阅读页独立；同一接触在原页边界结束笔画并保持捕获直到抬起，返回原页不续写；下一次接触可在另一页开始。斜线按最后一段与纸边的交点截断，避免简单坐标钳位改变方向。荧光笔、形状和橡皮保持原页归属。

文字合成保留已有单一输入表单和原页目标；对象拖动或双指变换的第二指落在另一页时，仍转交原对象。键盘、属性面板和存储错误只由一个输入页接管，避免重复撤销/错误 UI。已释放操作共享原队列和撤销历史；尚未写完/失败的页固定挂载，保存失败阻止转到其他输入页，明确重试会按原目标恢复。双指空白浏览统一中断未完成笔迹和橡皮预览，仍使用原有本机导航准入。翻页模式保留原交互。

自审覆盖输入生命周期、跨页事件路由/取消、原页指针捕获、虚拟列表卸载、失败队列和 undo/redo。相关笔记/阅读器组件 500 项回归通过；新增边界、共享历史、橡皮、跨页第二指、文字失败、延迟写入/失败保留和双指中断测试通过。全量客户端 1102 项（126 文件）、Node 测试 193 项（44 文件）、typecheck、lint、build/precache 检查通过。

真实系统 Chromium + 合成两页 PDF（DPR 2）验证：保留前页下半/后页上半并分别书写，越界不串页，撤销/重做，分别输入文字，跨边界拖动保持原页，注入本机保存失败后阻止错误交接并重试恢复，以及双指跨页浏览不新增多余笔迹。第一阶段的 60 页高 DPR/快速往返和重载保留笔迹/位置也再次通过。测试证据由 `visual-report/continuous-page-editing.test.mjs` 和 `reader-render-recovery.test.mjs` 写入 `artifacts/verification/`。

默认测试包含 Chromium/WebKit；本地 Cloud 的 Playwright 下载仍被 CDN 403 阻断，仅运行系统 Chromium。PointerEvent 浏览、quota/contextlost 注入及桌面浏览器都不是实体 Android/iOS 后台回收、惯性滚动、软键盘/Pencil 验收；这些需真实设备补验。此前预算缺陷的复现不代表已证实用户历史事故原因。
