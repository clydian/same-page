# 连续滚动渲染预算与单页恢复

起点 main `9015197`（含 #469、#471、#472）。合成 30 页 PDF 曾在 DPR 2、1200×2200 视口的七页窗口中抛出 `canvas_memory_budget`，释放预算后仍需点本页重试。该缺陷的复现不证明它就是用户 2026-10-17（或备选 18 日）下午那次故障的原因；生产没有已上传的客户端反馈可关联。

实现保持共享 24 Mi 像素上限和两个并发任务；可见页优先于预加载与缩略图，连续布局的可见页共享 12 Mi 像素目标，预加载限为 256 Ki，缩略图限为 64 Ki，并在高 DPR/宽页减少 overscan。预算耗尽后，资源释放或恢复前台会尝试恢复；画布丢失也可用新 backing store 恢复。同一挂载页最多两次自动重试，普通解析及超时失败保留手动操作。已打开的文档保持可读，错误留在单页。明确重新加载使用既有本机编辑完成与视口恢复协议。

故障界面及更多帮助不再提供原 PDF 下载；常规文件下载、附件及笔记导出不变。render 诊断只有固定原因和数字上下文，仍需用户主动发送，旧客户端/回滚兼容见运维说明。

验证：相关 reader/diagnostics/reader-page 组件回归 332 项，Node 诊断及相关 schema 26 项通过；预算优先级/取消、预算释放自动恢复、持久资源失败次数上限、解析失败不自动重试及既有后台挂起/恢复均有自动化断言。真实系统 Chromium 的 60 页高 DPR/高视口、快速往返滚动、上下文丢失、重载保留笔迹/位置与故障下载入口移除均通过。合成证据由 `visual-report/reader-render-recovery.test.mjs` 写入 `artifacts/verification/reader-render-recovery/`。

Cloud 下载 Playwright Chromium/WebKit 遭 CDN HTTP 403；本地使用 `/usr/bin/chromium`，双引擎测试保留给 CI。本报告不将桌面 WebKit 或触摸模拟称为实体 Android/iOS 验收；实体设备的惯性滚动、后台内存回收、软键盘与 PWA 仍待验证。
