# 操作反馈巡检与调整方案

目标是让反馈的位置和持续时间符合任务：用户做完一次操作后能轻松得知结果，继续工作；需要解决的问题则留在相关任务中。不是把所有 `status` / `alert` 都换成同一种浮层。

## 选择规则

| 情况 | 呈现方式 | 本次行为 |
| --- | --- | --- |
| 复制、恢复、清理等已确认完成的操作 | 固定位置的轻量 Toast，不插入正文 | 默认 5 秒，可关闭 |
| 打开 PDF、主动刷新等可重复尝试的读取失败 | 同一 Toast，说明失败与下一步 | 8 秒；原入口仍可重试 |
| 正在打开 PDF | 原行的图标、次要文字与取消按钮 | 不增加解释段落，不设“慢就是失败”的超时 |
| 输入错误、保存失败、保存已成功但刷新失败、结果未确认 | 留在表单或任务内，并保留恢复操作 | 不自动消失，不诱导重复提交 |
| 没有可用文件、已失权、未保存修改、本机笔记写入失败 | 页面、任务或编辑器自身的状态 | 保留必要说明和操作 |
| 持续离线、身份恢复、目录更新说明 | 连接面板按需查看 | 默认列表不常驻长说明 |

Toast 同时只显示最新一条，不堆叠或积压旧结果；用户悬停、通过 F6 进入通知区域或聚焦关闭按钮时暂停计时。关闭按钮有 44px 点击区域，键盘关闭后返回之前的焦点；普通结果使用 polite 状态播报。界面遵循深浅主题、安全区和减少动画偏好，阅读练习时避开底部播放控件。

## 已核查的相关入口

以下 11 处消费入口共用相同的临时反馈呈现；复用现有 `FeedbackMessage` / `useFeedbackMessage`，不在每个页面重复实现：

| 入口 | 临时反馈 | 同一入口中仍需保留的状态 |
| --- | --- | --- |
| `prepared-score-link.tsx` | 未缓存 PDF 打开失败 | 原行加载、取消；已校验副本直接打开 |
| `pull-to-refresh.tsx` | 主动刷新失败 | 原位置下拉进度；详细连接状态在面板中 |
| `invite-sharing.tsx` | 邀请方式复制、邀请卡生成、邀请码更新/保存完成 | 读写失败、输入问题和重新读取 |
| `trash-contents.tsx` | 乐谱恢复完成 | 名称冲突、恢复未确认、刷新失败 |
| `replaced-pdf-trash.tsx` | PDF 恢复为独立乐谱 | 恢复失败/不确定与重新读取 |
| `local-storage-page.tsx` | 本机文件清理完成 | 部分清理失败及重试选择 |
| `about-page.tsx` | 版本信息复制成功 | 复制失败时展开可手动复制的原文 |
| `diagnostic-report-form.tsx` | 诊断信息/反馈编号复制、本机诊断清空 | 发送进度、失败、反馈回执与编号 |
| `install-entry.tsx` | 安装网址复制成功 | 入口准备失败、手动复制和必要安装步骤 |
| `reader-display-notice.tsx` | 已恢复/保留原谱面的短暂反馈 | 无法显示时的恢复选择 |
| `practice-player-shell.tsx` | 浏览器全屏兼容性提示 | 播放准备失败、重试与无法退出全屏的操作说明 |

另外核查了 settings mutation、附件编辑/上传、登录、成员与用户状态、笔记保存/冲突、版本更新和运营发布页：其表单校验、写入不确定性、真实数据状态、更新安全条件与确认操作继续保留。已有版本提醒属于带后续入口的后台事件，不将其触发策略或跨窗口更新逻辑纳入本次改动。没有按字符串或 ARIA role 机械替换这些内容。

## 实现与验证边界

- 连接面板保持全局挂载，页面只提供按需说明；身份/目录刷新不重新创建已经打开的面板。
- 新增的是一个共用呈现位置，文档下载、离线准备、身份、业务保存结果仍由原模块判断。
- 使用锁定依赖中的 React Aria Toast；其当前导出带 `UNSTABLE_` 前缀，封装在共用模块内，没有增加依赖或依赖未安装的新接口。针对当前版本实际验证了空队列首次出现后的 F6、计时暂停和弹窗内关闭。
- 消息跟随发起页面/任务的生命周期；离开或切换目标后移除，旧计时器不会清掉新任务结果。
- 保留核心共用测试：临时/持久反馈的区分、阅读暂停与手动关闭、最新结果替换及卸载清理。PDF 自身保留失败重试和取消/改选等回归，不在每个复制按钮重复测试同一计时实现。
- 真实浏览器核对 PDF 失败/加载和复制时的布局、键盘进入与返回、弹窗内交互。截图使用本地合成数据；模拟视口不代表 iOS/Safari 真机验收。

参考依据：[W3C 状态消息](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html)说明无须转移焦点也应让辅助技术获知反馈；[React Aria Toast](https://react-aria.adobe.com/Toast)提供通知区域、键盘访问与焦点恢复，并建议只对非关键、可再次获取的信息使用自动消失。


本地回归还验证了目录后台刷新后的滚动/搜索/排序保留、显式离线保存与附件元数据、体验入口的网络提示变化和笔记隔离。连接线路完整 Chromium 回归使用本机 `app.same-page.localhost` / `alt.same-page.localhost` 替代受代理阻断的 nip.io 域名，保留同站点的独立主机及真实 TLS、cookie、跨域请求；验证冷启动切线、固定线路、面板跨恢复保持打开和结果未确认的写入不会重发。原域名与 WebKit 结果由 PR CI 检查，未把本地地址替换报告为原环境验收。
