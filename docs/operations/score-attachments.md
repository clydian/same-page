# 乐谱附件

对应 [Issue #331](https://github.com/itscly2026/same-page/issues/331)。默认列表只显示回形针数量，点击独立展开或收起对应乐谱的附件，互不影响，不提供全局开关。展开状态仅保留在当前列表会话。主乐谱阅读器保持独立。

主谱菜单只有“添加附件”一个附件入口，随后在同一弹窗选择音频、PDF、文档（仅 .md）或链接；音频列出全部允许扩展名，文件选择器按所选类型过滤并再次校验。文档可上传或直接编写，返回类型选择时复用未保存修改保护。文件信息与历史版本入口从主谱菜单移除，后台 PDF 版本与安全替换机制仍保留。

首版支持 HTTP(S) 链接、常见音频（MP3/M4A/AAC/WAV/FLAC/OGG/OPUS）、PDF 和 UTF-8 Markdown。TXT、DOCX 不在允许列表中。每份乐谱最多 100 个未彻底清理的附件（含回收站），音频 50 MiB、PDF 20 MiB、Markdown 1 MiB；主 PDF 仍为 20 MiB / 500 页。上限在 `src/shared/attachments.ts` 集中定义，修改时同步 SQL 的技术性上限。

音频使用原生控件，上传格式和浏览器解码能力分别判断；无法播放时可从附件行的“⋯”菜单下载。音频、PDF 和 Markdown 预览不提供直接下载按钮，已保存文件的下载统一保留在附件行菜单；Markdown 编辑中的草稿导出收在编辑器“⋯”菜单。文件流与 Range 响应复用同源鉴权通道，不提供公开桶或转码。PDF 使用与现有引擎匹配的 PDF.js 官方 viewer 组件，不进入乐谱工作区。Markdown 使用 MDXEditor 和 react-markdown，按需加载并排除专用模块的 PWA 预缓存。

## 数据与兼容性

- 增量迁移 `0027_score_attachments.sql` 新增附件及不可变内容记录，`0028_count_pending_object_deletions.sql` 为现有删除队列补充平台字节计量；部署先依次执行两项迁移，再部署 Worker/客户端。旧客户端忽略新增的可选 `attachmentCount`，原乐谱和 PDF 版本接口保持兼容。回滚代码时保留新表、对象与计量触发器，不能直接删除已有附件数据。旧删除队列中已无法追溯大小的条目保留原有计量行为；附件首发必须包含这两项迁移。
- 附件归属稳定的 Score。内容上传先预留配额，流式写入 R2 后按权限、父谱状态和 `revision` 条件提交；使用 `RETURNING` 确认目标行并返回本次写入的版本快照，不重新读取可能已被另一位编辑者修改的记录。不能把包含触发器效果的 D1 `meta.changes` 当作单行结果。
- 编辑 Markdown 产生新的对象，提交后旧内容进入持久删除队列。失败、取消和过期预留释放配额并补排对象清理；删除队列同时检查主谱版本和附件的引用。链接不创建文件对象。
- 普通附件删除保留三十天，可在现有回收站恢复；主谱删除/恢复决定其附件整体可用性，主谱或云盘彻底删除同步释放附件额度，后台保留期后物理清理，不重复扣减。
- 现有 `retained_pdf_limit_bytes` 名称为兼容保留，但平台上限合计免费云盘的所有主谱和附件对象，包括后台保留和待物理删除的对象。替换 Markdown 可以释放用户逻辑额度，但队列的 `platform_bytes` 持续计入平台上限，直到 R2 删除成功；删除失败保留队列重试，云盘级联清理前先记录字节，仍被文件引用的队列项不重复计量。
- Markdown 显式保存并进行版本校验。网络失败或冲突保留编辑内容、允许下载草稿；同标签页的草稿按本机身份、云盘、乐谱及附件隔离。新建文档首次确认保存后切换至实际附件 ID；早期预览误留在新建槽位的已保存草稿按原 ID 迁移，不覆盖其他草稿。导航/刷新保护不构成附件离线同步承诺。
- 显式退出登录会统计并清理当前用户的文档草稿。共享的退出代次保留至后续登录，其他标签页收到通知时清理；休眠标签页读取或迟到写入时仍校验代次，不能恢复已退出用户的旧草稿。它只用于撤销本机草稿，不授予云端访问权。
- 上传、创建、重命名和删除的结果核对使用操作权限保护的恢复接口，区别未创建、处理中、正常附件及回收站；父谱不可用和无权限不能当成“未创建”。未提交时保留原请求 ID 与输入并允许重试，处理中不重试；已删除且响应丢失时可以确认回收站结果。
- 暂时断网保留已打开表单、选中文件和原操作 ID，暂停提交并提示恢复连接后核对结果；明确退出、切换用户或新会话仍结束旧表单生命周期。
- 迟到的上传对象重新排队时更换删除任务 ID，清理任务只确认自己读取的 ID，避免旧清理轮次删除新任务；对象键保持不可变，队列年龄与字节保留。

## 加载过程的布局稳定性

附件等待和读取失败只呈现在所属乐谱的展开区域。首次读取按已知数量保留附件行空间，网络失败与重试保留其他已展开且版本未变化的附件。401、403、404 不保留旧元数据；身份、云盘、乐谱版本或写入代次变化仍按原边界失效，不把旧数据当作新权限。最后一个附件删除后，数量标记和等待区一并移除。

共用 `LoadingStatus` 只延后状态文字的视觉呈现 180 ms，不延迟点击响应、请求或结果。`SettingsFeedback` 保留状态行空间；路由模块加载和实际数据页使用相同标题与页头布局。附件、替换 PDF 和分享 PDF 在模块下载期间提供可关闭的弹窗，重模块继续按需加载；重命名和删除使用对应表单标题与尺寸。文档正文、编辑器和分享 PDF 在固定且受视口约束的容器中滚动。

`browser-tests/loading-stability.test.mjs` 暂停实际 API 和构建后的模块下载，检查文件行、状态区和标题的位置，检查等待时关闭后不会因模块迟到重新弹出，同时保留失败恢复和身份失效测试。

## 本地预览与验证

先执行 `npm ci` 和 `npm run build`，再执行 `node scripts/preview-score-attachments.mjs`。脚本使用隔离的本地 Worker/D1/R2，创建虚构用户和示例文件，输出仅监听回环地址的预览入口；点击入口会进入该临时用户的云盘。音频是合成测试音，PDF 是测试谱，均非生产资料。关闭脚本会回收临时存储。

预览入口和浏览器状态写在忽略提交的 `artifacts/verification/attachments-331/`。浏览器状态包含仅本地测试会话，不能作为截图报告附件上传或提交。可分享的截图仅取该目录的 PNG。

`worker/attachments-flow.test.ts` 覆盖真实接口、配额、并发修改、Range、类型校验与清理，包括待删除字节计量、迟到上传的队列确认和 100 个乐谱批量查询；`browser-tests/attachments-smoke.test.mjs` 用 Chromium/WebKit 验证实际 UI 的新建编辑、导入、普通 PDF、下载和恢复，`attachments-recovery.test.mjs` 覆盖草稿刷新后仍归属原文档，以及创建、取消上传、删除响应丢失后的结果核对与重试。真实 iPad Safari/PWA 的音频解码、播放拖动、PDF 下载及中文输入/选区/软键盘仍需单独验收。

本地音频检查使用 FFmpeg 生成的合成样本，七种扩展名在 Chromium 和 WebKit 中均已通过上传、播放及拖到第二秒；这只覆盖各容器选用的一种编码，不代表任意来源文件或所有设备。FFmpeg 仅生成验证样本，不是产品依赖。

浏览器回收站测试须等待删除弹窗关闭、附件列表刷新及恢复行消失后再跳页。`click()` 只表示已触发操作；紧接着整页导航可能取消仍在处理的恢复请求，在 WebKit 中还可能表现为请求访问检查错误。


## MusicXML 灰度能力（Issue #350）

依次执行 `0029_musicxml_attachments.sql` 和 `0030_musicxml_rollout.sql`，再部署 Worker/客户端。0029 在一个迁移事务中暂时移除相关触发器/视图，保留附件及内容记录、重建扩展 CHECK 的表，再恢复索引/触发器；不会执行用户文件删除或重复扣加配额。迁移测试覆盖现存附件、待上传、回收站和待删除字节。

0030 为云盘增加 `musicxml_enabled`，默认 0；经过预览和设备验收后由运维对选定云盘设为 1。能力接口与上传服务端都检查该开关；关闭设回 0，停止新的 MusicXML 上传并隐藏新播放入口，已经保存的文件仍可下载。不会为了回滚删除新文件或还原旧 CHECK。回滚代码应保留可下载 musicxml 的兼容版本；旧客户端不能显示新类型。

新客户端在附件元数据及 bootstrap 请求发送 `X-Same-Page-Attachments: 2`。旧请求维持四类型列表、对应数量和回收站；新协议显示 musicxml。鉴权与现有文件权限不变，能力协商本身不授予权限。上传内容支持 .musicxml/.xml/.mxl、单个 score-partwise、UTF-8/UTF-16；原文件不修改，下载仍为原始字节。原文件、解压后的 XML 各最多 20 MiB，最多 256 容器条目、15 个 score-part、100000 音符和64层XML嵌套；只解包声明的入口与 container，校验目录/CRC，不获取外部实体和资源。客户端 Worker 提前检查并提供具体错误，服务端独立检查，不信任客户端结果。

`@itscly2026/chorus-player` 由 Chorus 仓库维护；当前使用 vendor 中的固定安装包及 lockfile 完整性校验。升级从 Chorus 执行 workspace build/pack，再替换安装包、更新 lockfile并验证两个宿主；禁止生产依赖同级目录或动态 latest。播放器、解析 worker、音乐字体与音色不进入默认 PWA 预缓存。音色是合成练习参考，不演唱歌词。

附件开启后可播放、调速、关注声部、单独混音、小节定位和按播放次序设置 A–B 循环。返回所属 PDF 保留同一会话和紧凑控制，收起不销毁，结束/离开原谱/身份变化停止；已有原生音频会暂停 MusicXML，MusicXML 开始时暂停原生媒体。首次在线读取，断网不撤销已加载文件，但不保证刷新离线和锁屏持续播放。窗口恢复焦点重新核实附件权限。

本机练习偏好是可丢弃的速度、混音和位置，按本机身份、云盘、附件和修订隔离。准备失败可重试，音色/音频准备与文件保存是不同状态。不得把解析成功视作音乐内容校验结论。

验证：`worker/attachments-flow.test.ts` 包含灰度上传、旧协议列表/数量/回收站、原字节和非法 XML 配额恢复；`browser-tests/musicxml-playback.test.mjs` 使用合成乐谱检查 MXL 上传、实际浏览器播放状态、循环和原 PDF 交接。真实 iPad Safari/PWA 与 Android 仍须单独验收。
