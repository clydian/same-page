# 产品后台：运营授权与检查发布

对应 #433、ADR-0019。运营者仍需单独授权；已授权的运营会话默认覆盖全部云盘的当前有效乐谱，包括新建云盘，无需成员关系或逐盘启用。

## 上线顺序

1. 首次启用先备份并应用现有迁移 0032；升级全量范围时先应用增量迁移 0036，再部署兼容的新客户端与 Worker。0036 只替换最终发布守卫，保留既有数据、配额、运营授权与旧名单，不依赖预留迁移 0035。迁移本身不增加运营者。旧客户端无需升级即可继续读取正式附件。
2. 服务说明应明确已授权运营者查看全部有效原 PDF 与人工检查的用途。此版没有第三方内容传输。普通成员、拥有者和访客不会因此获得后台权限；运营者不能读取个人笔记或管理成员。
3. 使用已验证登录用户的稳定 ID 授权，不根据邮箱自动提权。维护者通过已有受控 D1 操作执行下列命令（本地用 `--local`，线上显式用 `--remote`）：

```sh
npm run admin:configure -- grant --remote USER_ID publish
```

`view` 只查看，`review` 增加导入与检查，`publish` 同时具有全部三项。不得给浏览器 Cloudflare 凭据。此工具不加入成员、不改变拥有权。

4. 已授权运营者访问独立入口 `/admin`，或经服务端确认能力后从“我的 → 产品后台”进入，沿用现有登录身份并单独校验运营授权。这里的运营者不是自动识别的角色：实际以配置的稳定用户 ID 为准；Cloudflare 账户、GitHub 身份或云盘拥有权均不会自动授予此权限。未登录时从 `/admin` 前往现有邮箱/Google 登录，成功后自动返回原后台页面，再由服务端校验授权。先用没有旧名单记录、运营者未加入的云盘验证原 PDF、XML 导入、检查与发布，再确认新建云盘自动出现。候选文件默认保留 30 天（来源 PDF 实际清理更早时随之移除）；产品侧默认 1 GiB，包括待上传预留和发布暂存。调整限额需维护者明确评估预算，不能绕过正式附件配额。

旧 `enable-drive` / `disable-drive` 命令及 `product_admin_drives` 记录保留给旧 Worker 兼容；它们不再控制新会话工作台的范围，不能用 `disable-drive` 撤销运营访问。受限 CLI 凭据的显式云盘范围仍是独立边界，不能据此扩大为全量，或获得人工检查、发布能力。

## 日常流程

需要通过终端查谱、下载、导入候选或查询状态时，使用[运营 CLI](admin-cli.md)。令牌在已登录的后台创建，限制云盘、只读或候选上传和有效期；检查与发布沿用网页流程。

跨云盘按谱名、云盘、状态找谱；选谱后查看原 PDF。导入 XML/MusicXML/MXL，绑定打开时的 PDF 版本，导入不会对成员公开。可切换候选与当前正式版，沿用现有声部、速度、首调数字、循环及谱面大小功能。人工核对由开发者自行决定，不要求逐项勾选。可以留下可选检查备注并保存草稿，之后再回来处理；确认发布时一并保存备注、记录检查通过，再执行发布。保存草稿会使结果重新待检查，不影响正式附件。

检查通过是人工决定，不是识谱精度保证。PDF 已变化、正式版修订冲突、用户已移除生成版或容量不足时，重新读取处理；禁止通过手动改数据补回用户移除的内容。

## 停用与回退

```sh
npm run admin:configure -- revoke --remote USER_ID
```

停用立即阻止后续接口与发布；已打开页面在回到前台或下一次接口请求确认失权后释放后台会话，已交付浏览器的字节无法远程抹除。停用不删除成员已有正式练习版。需要撤回正式版时沿用云盘附件回收站流程。

保留增量数据库表和旧名单，旧 Worker/客户端可以继续运行；旧 Worker 仍显示其名单内的较窄范围。不要通过回滚删除迁移或用户数据。后台的独立历史可在有效期内重新检查并重新发布；正式附件修订号始终向前。

## 清理与核查

每小时先清理到期候选、超过一小时的 pending/staging 与超过 90 天的操作记录，再运行现有 R2 删除队列。清理失败会重试。候选与正式文件相互独立，保留候选不延长来源 PDF 的用户恢复承诺。

验收需分别记录：增量迁移保持数据/配额、运营授权及能力分离、无名单/无成员关系的全量范围与新建云盘、发布 CAS/删除竞态、本地浏览器两云盘流程、普通用户播放器回归、最终 PR CI。上线后仍需单独授权运营者，不把本地浏览器通过当作线上配置或真实设备听感验收。
