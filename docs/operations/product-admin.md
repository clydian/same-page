# 产品后台：运营授权与检查发布

对应 #433、ADR-0019。运营者仍需单独授权；已授权的运营会话默认覆盖全部云盘的当前有效乐谱，包括新建云盘，无需成员关系或逐盘启用。

## 统一管理员与迁移 0039

所有产品后台功能共用 `product_administrators` 名单：发布通道、跨云盘乐谱查看／导入／检查／发布、问题反馈读取／标记／删除及审计。使用稳定 user ID 显式授权；云盘拥有者、受托权限管理者和普通成员不因此获得后台权限。管理员不自动加入云盘，不能据此读取私人笔记、管理成员或代登录。

```sh
npm run admin:configure -- grant --local USER_ID
npm run admin:configure -- revoke --local USER_ID
```

线上维护需要明确选择 `--remote` 并另行获得授权。本次 PR 不执行生产命令。每次 grant/revoke 都影响整个产品后台，不再接受 `view|review|publish`、`grant-release|revoke-release` 或 `diagnostics:operators` 分项授权。旧分项命令会失败，不会自动转换成全后台提权。`enable-drive|disable-drive` 已退役；历史 `product_admin_drives` 记录继续保留，不控制当前工作台范围。

迁移前后权限：

| 迁移前身份 | 迁移后 |
| --- | --- |
| 现有发布管理员 | 产品管理员，获得全部乐谱和反馈处理／删除功能 |
| 只有乐谱或反馈分项授权 | 失去后台权限；如确有需要，另行显式授予完整产品管理员角色 |
| 云盘拥有者／受托管理员／普通成员 | 不增加后台权限 |

已提供的只读生产调查：发布与乐谱名单各 1 人且为同一账号，反馈名单为空。因此按该快照，唯一发布管理员补齐反馈权限，没有其他账号新增或失去权限。部署前必须重新核实名单，不能将历史快照当成部署时现状，也不能取三份名单的并集。

部署步骤：

1. 沿用受控发布流程，记录 D1 恢复点，并保存三份旧名单及能力列供审查。核对预期迁入名单仅等于 `release_operators`，逐人审查完整后台权限变化。
2. 先应用 `0039_product_administrators.sql`，再部署 Worker／前端。迁移从发布名单复制管理员，将旧三张授权表替换为只读兼容视图；不改变成员关系、会话、反馈及到期日、候选文件、正式附件、配额或审计。XML 和发布提升的数据库触发器继续通过兼容视图执行最终授权检查。
3. 验证管理员可访问三个后台区域，云盘拥有者仍被拒绝，撤权后各区域与写入均立即拒绝。反馈删除确认、原子审计和删除标记继续生效。新增云盘自动纳入乐谱工作台；服务说明须明确全量原 PDF 的运营用途。

旧客户端继续理解原 `/admin/session` 能力字段；服务端为同一个角色返回全部能力。迁移后仍在运行的旧 Worker 通过兼容视图读取相同名单与全部能力，撤权同步生效。**迁移完成即切换权限语义**，不必等待新 Worker 部署；新 Worker 不能先于迁移上线。

代码回退保留 0039 和兼容视图，旧 Worker／客户端仍可运行，继续使用新版 CLI 管理统一名单；旧 CLI 对只读视图写入会失败。回退代码不会恢复旧分项权限。若要撤销统一权限模型，必须根据迁移前备份、迁移后授权变更另行审查恢复方案；不要盲目恢复整个数据库或删除迁移，以免丢失用户数据、恢复已撤销的权限。

## 日常流程

跨云盘按谱名、云盘、状态找谱；选谱后查看原 PDF。导入 XML/MusicXML/MXL，绑定打开时的 PDF 版本，导入不会对成员公开。可切换候选与当前正式版，沿用现有声部、速度、首调数字、循环及谱面大小功能。人工核对由开发者自行决定，不要求逐项勾选。可以留下可选检查备注并保存草稿，之后再回来处理；确认发布时一并保存备注、记录检查通过，再执行发布。保存草稿会使结果重新待检查，不影响正式附件。

检查通过是人工决定，不是识谱精度保证。PDF 已变化、正式版修订冲突、用户已移除生成版或容量不足时，重新读取处理；禁止通过手动改数据补回用户移除的内容。

## 停用与回退

```sh
npm run admin:configure -- revoke --remote USER_ID
```

停用立即阻止后续接口与发布；已打开页面在回到前台或下一次接口请求确认失权后释放后台会话，已交付浏览器的字节无法远程抹除。停用不删除成员已有正式练习版。需要撤回正式版时沿用云盘附件回收站流程。

代码回退与权限名单的处理见上文迁移说明；不要通过回滚删除迁移或用户数据。后台的独立历史可在有效期内重新检查并重新发布；正式附件修订号始终向前。

## 清理与核查

每小时先清理到期候选、超过一小时的 pending/staging 与超过 90 天的操作记录，再运行现有 R2 删除队列。清理失败会重试。候选与正式文件相互独立，保留候选不延长来源 PDF 的用户恢复承诺。

验收需分别记录：增量迁移保持数据/配额、统一管理员与云盘权限隔离、无名单/无成员关系的全量范围与新建云盘、发布 CAS/删除竞态、本地浏览器两云盘流程、普通用户播放器回归、最终 PR CI。上线后仍需单独授权运营者，不把本地浏览器通过当作线上配置或真实设备听感验收。
