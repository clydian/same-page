# MusicXML 离线播放

安装或更新合谱时，完整播放器资源与应用壳一起下载、校验和保存；所有必需资源完整后才允许切换版本。
播放器仍按需运行，普通页面不启动引擎或音频。在线打开 MusicXML/MXL 时保存原始附件字节。

- 构建输出版本化的 `playback/<buildId>/manifest.json`、字体和 soundfont 根目录；
  JS/worker/worklet 采用 Vite 内容哈希 URL。整个依赖闭包加入同一份应用壳清单，共享 JS/CSS 只保存一次。
- manifest 及其全部资源进入 shell 完整性清单，受安装、激活、安全更新和回收的同一套完整性规则约束；
  不下载未使用的 `sonivox.sf3`，保留播放器实际使用的 `sonivox.sf2`。
- Cache Storage 只保存可公开的资源。统一保存已解码响应，去除传输编码和 `Vary`；
  字体、worklet 与普通 fetch 的请求头差异不会造成离线缓存未命中。
- 原始字节使用现有 IndexedDB `system` store 中的 `offline-musicxml` 命名记录和 Blob 字段，
  不升级数据库版本、不改写 PDF/笔记数据。键包含 owner、云盘、乐谱、附件和修订。
- 激活写入同时检查本机工作空间 epoch、导航身份、附件目录拒绝标记、文件清理 fence、
  logout fence 和 AbortSignal。退出删除受保护原文；清理文件仅移除对应范围。
- 开谱时若本地读取超时或不可用而丢弃了最初的写入围栏，本次会话不会在下载或播放准备
  完成后自动重新捕获并保存。界面显示离线准备未完成，明确点击“重试离线准备”才建立
  新意图：先有界捕获当前本机围栏，再重新确认附件权限和修订；确认期间再次清理文件
  会拒绝写入。重试复用已下载的匹配原文，不重开播放器或再次下载，也不保留废弃缓存身份。
- 只有匹配的完整 shell、资源、原文、附件目录和已验证的主谱离线阅读条件同时满足，
  才显示“此练习谱可离线打开与播放”。没有主谱的完整离线副本时不作此承诺。
- 完整失败或中断保留旧内容；公共资源由应用壳统一修复，只补齐缺失/损坏项；支持从旧壳和旧播放器包按目标 SHA/大小及 MIME 复用字节。prepared 对象仍仅保留在
  原来的有界内存缓存里，不保存速度、位置、混音或声部设置。
- 播放器不再创建另一份公共包。准备和独立离线读取均请求 worker 核实对应完整版本；私有收尾路径只复用这一次校验；目录、主谱离线
  权限、原文 SHA 和本机围栏仍全部核实。以后独立的离线读取会重新审计磁盘公共包，
  不使用长期有效的“已验证”标记。
- 缓存中的目录是显示元数据。断网或暂时服务故障可使用验证后的原文；401/403/404
  明确拒绝不会回退。阅读器刷新后，缺少附件计数的 retained PDF 可读取最后保存的目录。
- 公共资源回收复用 #466 对活跃页面、worker、回退壳的保护及现有版本回收规则，不能触及业务存储。

## 验证

`browser-tests/musicxml-offline.test.mjs` 使用持久 Chromium profile：
上传 XML/MXL、确认完整版本就绪、关闭整个浏览器、断网启动、从目录进入 MXL、谱面实际渲染、
非零音频采样、暂停、速度/声部设置、刷新、从阅读器进入 XML、再次实际出声和暂停；
随后注入附件 403，验证当前原文被清除、其他原文和 PDF 保留。
截图输出到 `artifacts/verification/musicxml-offline/`。

构建单测验证资源 URL 隔离、静态依赖闭包及共享依赖去重。存储与资源测试覆盖
中断、重复准备、版本不符、损坏/被清除的缓存、配额失败、清理、退出 fence、
切换用户后返回、导航重置和迟到写回。既有 MusicXML 浏览器测试同时覆盖 Chromium
与 WebKit 的 Worker、声部、循环、实际音频、速度和 PDF 切换。

本地命令：

```sh
npm run lint
npm run typecheck
npm run test
npm run build
node --test browser-tests/musicxml-offline.test.mjs browser-tests/musicxml-playback.test.mjs
npm run test:pwa-update
```

原离线播放实现的验收环境为 Linux 系统 Chromium 154、Playwright WebKit 26.5。
Playwright Chromium 的 CDN 下载受限，测试使用系统 Chromium；WebKit 的缺失依赖解包到
临时目录后运行，没有修改应用依赖或部署系统。真实 iOS Safari/已安装 PWA 的杀进程、
后台回收、音频路由及系统存储淘汰仍需真机验收，不能由桌面 WebKit 结果代替。

原离线播放 PR 未修复的 AudioWorklet 初始化快速暂停竞态（#434），后由固定的
player `0.1.19-samepage.2` / native `1.8.4-samepage.3` 修复：同步启动静音 source，
并隔离暂停、结束、释放之后迟到的初始化回调。构建来源及回归范围见
`vendor/chorus-player-0.1.19-samepage.2.md`；不将桌面浏览器自动化视为手机真机或耳听验收。


跨版本回归：`node scripts/verify-playback-upgrade.mjs`。使用两次真实生产构建、
独立持久 Chromium profile 和合成成员/API 数据：旧版本保存 MXL，注入新版必需
引擎下载失败确认旧版继续运行，恢复下载并切换，关闭浏览器后断网重开，验证
原有 MXL 无需再次联网打开、实际排版、非零声音采样以及刷新后再次打开。
该脚本已加入 `npm run test:pwa-update`；可通过
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定本机 Chromium。

本次必需播放器更新的 CI 根因、收敛方案及验证记录见
[完整播放器安装复核](required-player-install-review-2026-10-28.md)。真实后端的
XML/MXL 离线冷启动、实际音频、刷新与失权回归已通过；浏览器集成验证不能由
模拟接口的跨版本专项测试替代。桌面 WebKit 不等同于真实 iOS/PWA 设备验收。


## 首次准备与更新进度

首次访问时即可能开始准备资源；添加桌面图标并不等于离线资源已完整。
安装引导、安装页与关于合谱共用安装 worker 的真实准备状态：先检查/复用本机
资源，再接收缺失资源，最后校验并保存，worker 确认安装完成后才显示就绪。

进度条按已验证并写入缓存的文件字节数 / 当前版本清单总字节数计算；单个文件
下载期间，另行实时显示已接收的解码资源字节。后者不是压缩网络流量或永久存储
占用；换线重试从新尝试重新计数，不拼接失败线路的字节。缓存复用单独计数。
下载接收完成不会提前授权切换；最终完整性审计、存储提交、版本许可和原有多窗口
安全协议仍独立生效。准备完成与等待安全切换分别显示。

进度通知限频并补发最后快照。页面只接收当前安装 worker 的有效递增快照，忽略
其他 worker、旧尝试及乱序消息；重新进入页面主动查询当前快照。旧 worker 不支持
进度协议时显示不确定进度，不猜百分比。消息不包含资源 URL、文件名或业务内容。
回归同时检查 390px 布局、首次真实流式接收、更新缓存复用，以及断网 MXL 排版/音频。
