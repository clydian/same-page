# 登录会话有效期与续期

关联：[#358](https://github.com/clydian/same-page/issues/358)。

密码与 Google 登录使用同一会话策略：有效期 180 天，每次成功的在线会话校验重新计算 180 天（Better Auth `expiresIn: 15552000`、`updateAge: 0`）。这里的使用指服务端收到带有效登录 Cookie 的认证或产品访问；离线阅读、仅访问静态资源和访客访问不续期。每次校验更新数据库并返回 Cookie，比按天续期增加 D1 写入，但避免将未使用期限缩短最多一天。

认证入口的用户删除预检查禁用续期，由实际认证响应负责 Cookie。产品接口通过 `readContextSession` 转发所有 `Set-Cookie`，并禁止缓存响应；没有 HTTP 响应通道的身份检查只读会话，不更新期限。不要新增丢弃续期响应头的 `getSession` 调用。

## 发布与兼容

只发布 Worker 代码，无数据库迁移、Cookie 更名、令牌轮换或本地存储变更。旧客户端继续使用相同 API。尚有效的七天会话在下一次有效在线校验时自动延长并收到新的 Cookie；已经过期或设备已经删除的 Cookie 无法恢复，用户需要重新登录。上线后没有再次访问的旧设备仍受原有效期约束。

另一设备登录或普通退出不撤销当前设备。密码重置仍撤销所有已有会话；用户删除仍立即阻止产品访问，恢复验证和三十天恢复窗口不变。延长会话不会替代敏感操作的重新验证要求。设备主动清理站点数据也仍可能要求登录。

## 验证与回滚

`npx vitest run --config vitest.worker.config.ts worker/auth-flow.test.ts` 覆盖新登录期限、旧会话经认证/云盘/用户状态接口续期、过期拒绝、多设备隔离、密码重置和用户删除。

发布后用测试用户检查登录与产品 API 返回的 `Set-Cookie` 包含 `Max-Age=15552000`，不要记录令牌值。回滚可恢复代码而保留数据库与用户数据；已经发出的长期 Cookie 和数据库期限不会自动缩回七天。若仅调整期限，应保留响应头转发修复；不要批量删除会话来回滚。
