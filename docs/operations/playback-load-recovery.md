# 可选播放器加载失败与部署更新

历史问题 #446：旧页面可能一直保留旧版应用壳；播放器是按需下载的模块，且有意
不进入 PWA 预缓存。旧部署方式替换哈希文件后，旧页面首次打开播放器可能请求
已经不存在的旧模块。当前 ADR-0021 使用不可变 `/_releases/<sha>/` 归档，
旧页面仍可读取自身版本的模块；发布新版本本身不应禁用播放器。安全更新会保留仍在工作的页面，并允许其他窗口否决切换，
不能用自动刷新或清空站点数据处理这个失败。

播放器区域现在有独立错误边界。模块加载或播放器渲染失败会切回 PDF，保留
阅读器、笔记编辑器和全局更新监听。错误区显示更新检查结果，提供关闭播放器、
检查更新和关于合谱入口。检查只准备更新；完成当前操作后，用户仍通过关于
合谱的既有安全交接应用更新。其他窗口否决时继续保留当前版本。

`assets`、`pdfjs`、`font`、`soundfont` 四个静态资源目录通过 Worker 的 ASSETS
绑定读取。真实资源保留原字节、MIME 与缓存头；缺失响应或 SPA 回退 HTML
转换为 `404 + Cache-Control: no-store`，不再将 HTML 按模块 URL 缓存一年。
正常页面导航仍沿用 SPA fallback，API 路由不变。代价是这些目录的请求增加
一次 Worker 调用。这是 #446 当时的保护措施；当前旧构建资源托管由 ADR-0021 的发布归档提供，播放器仍不扩大预缓存。

已运行的旧客户端仍须按原更新流程切换后才能获得错误边界。这个补丁不能
热补已经加载的 JavaScript，也不能收回浏览器此前缓存的旧模块 URL 响应。

回归：`playback-gate.test.tsx` 拒绝实际 lazy import，确认未保存输入保持同一
DOM 和内容、回到 PDF、可见更新反馈及可关闭。`static-assets.test.js` 覆盖
HTML 回退、404 缓存头和真实文件透传。真实 Chromium/WebKit 的
`playback-load-failure.test.mjs` 从成员阅读器打开附件，注入相同 HTML/MIME
加载失败，确认 reader 根节点/PDF 未卸载、检查更新不导航，并通过实际本地
HTTP 验证四个目录的缺失资源和正常 SPA/脚本响应。桌面 WebKit 不代表真实
Safari/PWA 验收；原多窗口 PWA 更新测试继续保护交接策略。

部署后核对旧 `/assets/musicxml-player-BRJQwkJT.js` 返回 404/no-store，当前
build.json 中的脚本仍返回 JavaScript/immutable，再从成员附件入口实测播放。
不要通过清站点数据、强行激活 worker 或关闭其他使用中的窗口绕过安全策略。

## 慢网络与准备反馈

前台准备依次确认访问权限、读取本机缓存（250ms 预算）、必要时下载乐谱原件，
再由 Worker 处理乐谱、建立模型、生成播放数据。音色加载和谱面排版可与后半段
并行；界面只显示当前仍在等待的阶段，不把并行工作编造成固定步骤百分比。
下载进度使用已授权附件大小和实际接收字节；音色进度使用引擎的实际加载事件。
处理、生成和排版没有可靠工作量时使用不确定进度。可播放且首个谱面可读后，
离线保存才在后台启动，不阻挡播放。

附件读取与引擎准备各自有 180 秒上限（原为 60 秒；两段最坏可累计约 6 分钟），
明确网络或解析错误仍立即反馈。单阶段持续 30 秒后提示可继续等待，并提供显式
重试；重试中止旧读取、销毁旧引擎，晚到的完成事件不能恢复失败或已关闭的任务。
不无限延长等待，也不自动重复下载。

播放器模块加载失败与上述准备超时不同。错误边界保留阅读器及未保存内容；
提示检查网络，持续失败后通过关于合谱的安全流程检查版本。React.lazy 和浏览器
都可能记住失败的模块加载，单纯重建 lazy 包装不构成可靠恢复，不能用一个无效
重试按钮掩盖这个限制，更不能在阅读器中强制刷新或清理数据。

回归覆盖 61 秒后仍可完成、180 秒截止、晚到事件、真实下载/音色进度和重试取消。
`visual-report/playback-preparation.test.mjs` 在 Chromium/WebKit 手机尺寸下，
从成员附件入口打开真实播放器，暂停原件下载检查阶段及截图，再放行直到可播放。
这不等同于真实 iPhone 弱网及后台恢复验收。
