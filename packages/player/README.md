# Same Page Player

Same Page 私有播放器模块，源码、测试和构建均由本仓库维护。 `./format` has no browser/audio dependency and performs bounded XML/MXL admission. `./engine` preserves the existing MusicXML timing and dynamics corrections. The main export provides an owned playback session.

Hosts supply bytes and a container, own authentication/navigation and dispose the session on scope changes. No private scores, room configuration or credentials are included. Install alphaTab's matching Vite plugin in browser hosts to copy fonts/soundfonts and bundle workers; configure lazy loading and PWA exclusions in the host.

在仓库根目录执行 `npm run build:player` 或 `npm run test:player`。根项目通过 npm workspace 使用本地构建，无需发包或其他产品仓库。alphaTab 保持精确 peer；修改原生引擎见 `../../vendor/alphatab/README.md`。


The engine collects simple numeric MusicXML metronomes and `sound/@tempo` before
import. Beat units and dots become quarter-note BPM; offsets are converted from
the current divisions at the direction cursor, including backup/forward voices.
Explicit sound tempo wins at the same onset, and sound-only automation stays
hidden. Preparation carries this timeline to the engine without rewriting the
original metronome notation. Older prepared payloads use a byte-parser fallback.
Metric modulations, tied units, tempo ranges, pass-specific `sound/@time-only`
and negative out-of-measure onsets
leave that measure's native automation unchanged and require source review.

alphaTab's native metronome glyph uses a quarter note and equivalent BPM. The
source XML retains its original half/dotted beat mark for export and source
inspection; this correction does not provide exact beat-unit glyph rendering.
Validate the actual MIDI tempo timeline, not merely the XML or UI tempo label.
Run `node --experimental-strip-types --test test/musicxml-metronome.test.mjs`
for the focused regressions, then `npm test` and `npm run build`.


For an acoustic-grand-piano track (named Piano / Pianoforte / 钢琴, or the
bounded full label Keyboard reduction (optionally followed by "(for rehearsal only)"), initial GM
program 0 and bank 0), simultaneous voices can represent one physical key.
`createPlaybackApi` installs a public `midiLoad` hook that retains one attack at
the greatest source velocity and holds it until the latest source note-off.
Both written voices and their stems remain in the source and notation model.
Current program and bank controls are evaluated in native event order; other
instruments, tracks, channels and later reattacks are retained. Native control,
bend, rest and end-event order is preserved. Only the normal single-track,
multichannel MIDI generated by AlphaTabApi is adapted. A candidate requiring
repair incurs another MIDI generation pass; ordinary non-piano loads are no-ops.

For playback audits, generate MIDI with `applyTranspositionPitches=false`, then
call `preparePianoPlaybackMidi(score, file, settings)` from `./engine` before
synthesis. Direct native MidiFileGenerator output still contains both written
voices. Native `api.exportAudio` / MIDI download are separate paths and are not
changed by the playback hook. Do not describe those exports as corrected.
Run `node --experimental-strip-types --test test/piano-shared-attacks.test.mjs`
for the pre-synthesis regressions. Actual SONiVOX/AlphaSynth comparisons verified
sample-identical output against the one-attack/longer-hold reference; this is
synthesis evidence, not a claim of human listening or complete score acceptance.


MusicXML `time/@print-object="no"` is respected on the corresponding standard
notation bar/staff through the public `BarStyle` time-signature paint color.
Unnumbered time applies to that part's staves; `time/@number` selects one staff,
including explicit visible overrides. Part IDs are mapped using `part-list`
order (not document part order or instrument names). Preparation carries plain
visibility metadata through Worker/structuredClone; old prepared callers fall
back to their XML bytes. Host source bytes, meter, notes, tempo and tick lookup
are unchanged, and other bar styles are retained.

Visibility collection is a pure XML module; it must not import alphaTab's runtime
entry point into `prepare.worker`. That entry point initializes renderer/synth
Worker protocols on import and can make the host consume an unrelated message
instead of its prepared score. Painting is loaded with the playback engine only.
The actual built preparation Worker and full playback/PDF handoff were verified
in Chromium and WebKit in the Same Page host; Node-only cloning is insufficient
to verify this browser Worker boundary.

The native glyph still reserves layout space. This is a paint correction, not
a new engraving engine. Only the measure containing the explicit hidden time
is changed: native repeated system-start meters elsewhere retain their normal
behavior. Native omission of a later visible redeclaration of the same meter
is not corrected. Non-standard notation profiles, score-timewise, duplicate or
unmappable part/staff/time declarations are outside this correction; ambiguous
measure mappings retain native rendering. Default namespaces are supported;
namespace-prefixed root admission remains subject to the existing native format
detector. Full polymeter support is not added.
Run `node --experimental-strip-types --test test/musicxml-hidden-time.test.mjs`
for actual SVG, serialization, source-byte and exact MIDI/tick regressions.
Gradual text (`cresc.`, `dim.` and their existing supported variants) is inferred
only until the next applicable explicit source dynamic, even when that mark
repeats the current value or contradicts the gradual direction. A directional
mark still supplies the ramp target; an equal/opposite mark stops inference and
restores its source value. Staff/voice resets stay scoped; the existing policy
for one-staff, non-voice-scoped piano dynamics remains part-wide for playback.
Source offsets are honored even between note attacks. Following gradual words
and hairpins retain their existing boundaries. Older direct correction callers
without source-event metadata retain their legacy beat-based behavior. This
changes playback velocities, not printed marks, pitch, rhythm or source bytes.
Run `node --experimental-strip-types --test test/gradual-word-reset.test.mjs`
for actual MIDI regressions, including equal MF, opposite/directional targets,
scoped resets, intervening instructions and offset boundaries.
At one onset, effective dynamics follow the same rule for carried playback,
ramp targets and source-onset restoration: the most specific staff/voice scope
wins, then the last source declaration at equal specificity. Visual beat marks
keep their own staff scope; piano part-wide playback remains separate. Scoped
endpoints preserve the existing shared note-onset grid for ramp interpolation.

Gradual-word inference ignores an immediately negated Italian instruction such
as `non dim.` or `non cresc.`. The original text remains visible and its notes
retain the carried source dynamic; no replacement dynamic or glyph is invented.
Negation applies to the following gradual term, not the whole direction:
`dim. non troppo` and `non troppo dim.` still diminish, and `non dim., cresc.`
still crescendos. This is a bounded lexical rule for `non` directly preceding a
supported gradual term, not a general natural-language or Italian-expression
interpreter. Mixed affirmative instructions retain the existing crescendo
precedence. Run `node --experimental-strip-types --test test/negated-gradual-words.test.mjs` for source-text and actual MIDI controls.

MusicXML wedges retain their source measure, fractional quarter offset, number,
staff and voice before alphaTab direction reordering. Playback marks only note
onsets in the original half-open start/stop span, including a stop inside a held
note; it does not insert rests or move that stop to the next onset. This prevents
an offbeat stop from leaking a gradual velocity change past later explicit
`mf` marks. A continuous change inside an already sounding note still requires
an expression controller and is not synthesized as extra attacks.
For arbitrary nonnumeric MusicXML voice tokens whose imported voice index cannot
be resolved, this recovery conservatively retains native wedge markers instead
of clearing them. It does not claim corrected offbeat playback for those lanes.

Wedge span identity follows its source number, even when a stop omits staff/voice
or is placed on another staff; the start retains playback scope. Concurrent active
reuse of one number is ambiguous and retains the previous native-marker path
rather than inventing unbounded spans.

### Source creator credits

Typed MusicXML composer and arranger credits remain distinct in the rendered
header. alphaTab maps an arranger to its generic `music` field, which otherwise
prints the misleading “Music by” label. The adapter preserves source creator
roles in plain preparation metadata and renders explicit composer/arranger lines.
It leaves lyricist credits and score bytes intact, does not invent a composer,
and retains existing header behavior when no typed arranger is present. Legacy
prepared payloads recover the metadata from their XML bytes. This display change
does not alter notes, channels, tempo or MIDI events.

### Relative metronome playback

Simple source metronome equalities such as dotted-half = whole scale the preceding
quarter tempo by the right/left beat-unit lengths. Resolution follows global
written measure/onset order, deduplicates simultaneous part copies, and gives an
explicit same-onset `sound tempo` precedence. The existing opening default 120 is
playback policy, not a source metronome. Derived numeric BPM values are hidden so
that an equality does not invent a printed number. Tied-unit/tuplet/range and
pass-specific marks retain native fallback; an unknown carried tempo cannot seed
a later relative mark until a new supported absolute tempo establishes it.
When an explicit playback `sound tempo` differs from all printed numeric marks at
the same onset, its winning value is hidden instead of being printed as source.
This also hides the original printed number in the current native numeric-tempo
renderer. Source numeric marks and equalities still need an independent display
layer; playback correctness here is not a claim of complete visual preservation.

### Source dynamic glyph anchors

After all playback ramps and source-onset velocity restoration, a separate pass
may reduce carried `beat.dynamics` to exact source glyph anchors. It never changes
`note.dynamics`, MIDI notes, tempo or source XML. A pure preparation completeness
flag gates the pass. Older prepared payloads without that flag retain their prior
marker path, as do tracks with compound/unsupported dynamic declarations.

This local prototype requires the unpublished native `Beat.isDynamicsExplicit`
API (alphaTab source commit `4cd8c3f`). It can draw an exact source declaration
on a rest, a repeated same-value declaration, or an existing empty cross-staff
beat anchor. An existing visible beat is preferred over a placeholder at the
same source time. No beats, notes or durations are added. The native flag survives
JSON conversion and cloning; both the preparation Worker and native rendering
Workers were exercised in the isolated Chorus browser Session.

The whole track is preflighted before any visual value is cleared. Nonnumeric
voices, source marks with no exact staff/voice/time anchor, and conflicting mapped
signs retain the previous whole-track marker path. These fallbacks can still
contain extra or missing glyphs. Finzi Piano14's staff1 mp at quarter3.5 has no
native staff1 beat because the voice moves to staff2, so that track still falls
back; this prototype does not move the mark to another staff or later note.

This branch is not releasable with the declared official alphaTab1.8.4 alone.
The native fork dependency and its reproducible distribution must be pinned
before packaging or creating a host integration. Current local browser/MIDI
proofs are not a SamePage deployment or complete score acceptance.

A producer `dynamics print-object="no"` hint also retains the whole prior track
path. MusicXML 4 does not define that attribute on dynamics; this conservative
fallback does not claim native hidden-glyph support.


### Mixed numbered and unnumbered ties

Complete, adjacent, unambiguous source ties are assigned importer-safe IDs in
ordinary parts as well as transposed parts. alphaTab 1.8.4 leaves an already
consumed numbered origin in its pitch-only fallback set; a later unnumbered stop
can otherwise replace that completed chain's destination. This repair preserves
source pitch, rhythm, scope and attachment bytes, including when loading cloned
prepared metadata. Sequential ties may reuse IDs after their XML-order endpoint.

If any unnumbered endpoint in a part cannot be paired safely (incomplete,
ambiguous, cross-voice/staff or unsupported notation), the entire part keeps its
native import path. A grace note carrying any `tied` endpoint also forces whole-part
native fallback: grace timing is not inferred by this finite-duration model. This
prevents creating a new stale numbered origin that an
unresolved unnumbered stop could consume. It does not certify or repair native
behavior for those unsupported parts. Polymetric timelines and exhausted ID
budgets also retain conservative fallback; no rests or missing ties are invented.


### Repeated work and movement titles

MusicXML may legally give work-title and movement-title the same text. After
import, an identical nonempty title/subtitle display line is rendered once.
Different headings (including case differences), title-only and movement-only
headers remain distinct as imported. This display correction does not remove
attachment XML fields or change prepared source metadata, score music or MIDI.

### 源渐变线与多声部显示

`loadMusicXml` / `loadPreparedMusicXml` 先完成全声部的力度与渐变播放计算，再单独恢复渐强／渐弱的显示。一个未指定 voice 的源谱表记号，若能在该谱表的一条原有 voice 中找到连续且起止完全相等的拍段，只在这一条 voice 上交给原生渲染器绘制，避免持续音所在的多个 voice 分别画一条重叠线。不插入隐藏拍，不移动音符，不改变 note dynamics 或 MIDI。

声部超出小节时间、无法精确表示端点、未闭合或孤立的跨度、同编号并行复用、未知 voice、不能用原生分组分开的相邻同形跨度，整轨保留此前的标记路径；旧 prepared payload 缺少源 wedge 元数据时也不推测。这是有界的形态修正，不代表完整源排版验收：`spread`、`niente`、线型、颜色与上下位置未由此恢复，次声部颜色仍遵循原生渲染；休止上的力度和歌词延长线另行处理。

回归覆盖真实失败模式的三个 voice（长持续音与活动声部），实际 SVG 的一条源渐弱从三条重叠形态恢复为一条，并逐字段核对 MIDI、拍边界和音符时值不变；跨小节、明确 voice、Worker clone 与不支持情况分别验证。

### 源力度的上下位置

预处理在 `dynamicEventsByPart` 中保留 `<direction placement="above|below">` 的可选位置，并通过原生 `Bar.sourceDynamics` / `SourceDynamicPlacement` 上下两个排版 band 绘制。标为 above 的小节使用完整的独立时间声明列表，即使该谱表在记号时刻没有 note/rest beat，也不移动到前一拍、不插入隐藏拍。未指定位置和旧 prepared 元数据保持原有 below 行为；这不改变播放力度、音符或时间线。

按 [MusicXML dynamics 规范](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/dynamics/)，direction 内的 dynamics 自身 placement 不生效，此处以 direction placement 为准。此路径仅恢复明确的上下侧，不处理 `default-y`、`relative-y`、note-associated dynamics 或同一时间多个独立 voice 的冲突记号；这些情况不据此宣称原谱排版已完整验收。运行时必须使用包含该公开原生 API 的同一 alphaTab 模块实例，原生 fork 的打包与依赖版本由宿主集成单独管理。


### Native source package for 0.1.18

This version requires the exact `@coderline/alphatab` peer `1.8.4-samepage.1`,
installed by the host from the reviewed local tarball. The source repository pins
that artifact in `vendor/`; it is a modified build, not an upstream npm release.
Do not install a second nested native runtime or replace it with official1.8.4.

Before distributing a browser build, copy the matching complete modified sources
and license notices into the host's versioned public directory:

```sh
node packages/player/scripts/copy-native-source.mjs --output public/third-party/alphatab
```

The source app invokes the same helper from `packages/player/scripts` before its
build. It validates the installed peer and enclosed archive checksum, uses
content-addressed filenames, rejects altered existing snapshots, and retains old
versions. Commit new snapshots and keep older ones when updating the native
package. See [native distribution](../../vendor/alphatab/README.md) for
clean-build and source-replay requirements. A private repository URL alone is not
the source distribution for a public browser runtime.

### 0.1.19-samepage.7: source words font families (SamePage #501)

### 当前原生版本：源谱连梁与延长记号

当前精确原生 peer 为 `1.8.4-samepage.14`，分发源码提交为 `c91004f04ec585fd588bdffc71f5c6d4f0dd02e9`。同一 MusicXML 逻辑声部中，完整、等时值、等附点且符干方向兼容的显式连梁组可以跨谱表绘制；休止、提示音、不完整组、hook 及不兼容的时值或符干保留原有回退。它不从连线推断连梁，也不复刻原谱的任意斜率或坐标。支持范围见原生覆盖层的 `docs/musicxml-cross-staff-beams.md`。

MusicXML 延长记号按实际声明的拍与声部绘制，保留 normal、angled、square 形状及 upright／inverted 方向；倒置记号位于谱表下方，不再把小节级播放继承值复制成其他拍的印刷记号。新增归属和方向经 JSON／Worker 保留，旧 JSON 仍采用原有默认行为。此次没有增加延长记号的实际播放停留时长，不能据此宣称自由速度或整曲演奏已经验收。细节见 `docs/musicxml-fermata-scope.md`。

播放器运行代码与既有版本相同；本地 workspace 更新精确 peer，不重新发布历史 Chorus 制品。旧原生包及公开源码快照继续保留。最终安装制品和实际产品 Worker 仍需分别验证。
