# 视唱挑战：谱面、回听与最佳成绩

产品构建 commit `00364e5a8fec4fc22a8a7b6b7daef1a1753b5f3e`。在 Chromium 手机（390 × 844，简体中文浅色）和桌面（1230 × 1000，英文深色）运行同一份生产构建。预览数据是合成谱与示例账号。

| 路径 | 浏览器验收 |
| --- | --- |
| 准备 | 全部声部显示，选唱 Alto，五档调速与谱面速度同步。120 BPM 原速在 0.75× 时显示 90 BPM。两个可独立开启的伴奏设置均弹出可关闭的耳机提示。 |
| 预备和演唱 | 使用 Chromium 假媒体设备和 48 kHz 标注 PCM，音频走同一 AudioWorklet、Pitchy 和逐音评分。四个轮次为低八度同音名、偏高约 35 音分、错音和静音。 |
| 结果 | 两种视口均显示 25 分、唱准 1/4。四个符头和三个独立符杆着色；和弦共享符杆保留原色。 |
| 回听 | 从零绘制谱面轨迹，停止后轨迹及位置保持，再次点击续播。点第二小节的第二个音从该小节起点 2.667 秒附近播放。 |
| 最佳成绩 | 完成自动写入示例云盘榜。八小节题查看全部版本时示例账号显示 V1 的 88 分，选择 V2 时显示其 76 分；撤下 V1 后「全部版本」显示 V2 的 76 分。 |

`verify.mjs` 检查上述阶段，也记录浏览器异常与传出的 API 请求。两个视口均无此类记录。运行需要在产品仓库有 Playwright 的环境中，提供由同一 SHA 构建并加入私有试玩夹具的本地站点。可通过 `SIGHT_QA_URL` 指定 URL、`SIGHT_QA_BUILD` 指定产品 SHA，运行 `node /path/to/verify.mjs /tmp/sight-singing-evidence`；加 `SIGHT_QA_THEME=dark` 运行桌面英文深色。

产品仓库另跑了单元、TypeScript、改动文件 ESLint、i18n 和生产构建。Worker/D1 集成覆盖较高成绩覆盖、低分和同分保留原条目、同时提交、跨版本、新旧请求格式、退出云盘后的读取限制、本人撤下与重试。SQLite 检查了已有成绩在新迁移后保留早到的并列最高分，保留历史原表及未知速度。

预览的发布与撤下写入本标签页模拟资料，手机屏幕截图来自浏览器模拟视口。iPad Safari、主屏幕入口、真人耳机与麦克风路由仍需真机确认。
