# 云盘入口设计预览（临时）

问题：已有云盘切换器和启动恢复后，独立「我的云盘」页还应承担什么任务？首次尚无云盘的用户如何开始？

本分支只用于评估设计，不直接合并到 main。用户选定方向后另行实现，保留原有登录、离线和失权边界。

运行：`npm run preview:drive-entry`，打开 http://127.0.0.1:4189/drives?variant=C&case=multiple 。页面下方可切换三个方案及用户状态。也可用左右方向键切换方案（表单输入及交互控件中不拦截）。

- A 轻量选择：页面只负责选择；加入、创建降为次要动作。
- B 继续排练：强调上次打开的云盘，其余云盘可展开。
- C 直接进入：在本机已知上次目标或仅一个云盘的示例中直接呈现现有文件库，复用左上角的云盘切换器；没有明确目标时用轻量选择。新用户看到邀请码加入，创建作为次要入口。

建议 C 为日常路径，以 A 承担无上次记录和失效目标的兜底。这是待用户确认的建议，不是已选定方案。

预览状态包括当前示例身份、零云盘、单云盘、多云盘且有上次记录、离线示意、上次目标不可用。使用隔离的合成身份和曲谱，不调用生产。加入/创建仅改变当前组件内存。离线状态用于比较呈现与操作权限，不是浏览器真实断网或实机验收。

已人工检查：三种布局、真实文件库与切换器、首次加入后进入示例云盘、失效目标兜底、320px实际CSS视口无横向溢出；邀请码输入52px、主要操作48px。TypeScript与相关lint通过。原型不新增测试。

正式实现仍需验证：启动/显式进入/浏览器返回分别处理；0个、1个、多盘无历史、多盘有历史；上次云盘失权；目录读取失败不得伪装为空；离线目录不授予云端权限；原有个人菜单、加入与创建、草稿和同步归属完整保留。
